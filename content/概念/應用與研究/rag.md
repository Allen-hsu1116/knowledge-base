# RAG（檢索增強生成）

> 結合外部知識檢索與 LLM 生成，讓模型回答有根據、可追溯，是 LLM 應用從玩具到工具的關鍵一步。

## 核心內容

RAG（Retrieval-Augmented Generation）是一種讓 LLM 在生成回答前先檢索外部知識的技術架構。核心流程：使用者提問 → 系統從知識庫檢索相關內容 → 將檢索結果作為上下文餵給 LLM → LLM 基於檢索內容生成回答。

RAG 解決了 LLM 的三大先天限制：**知識截止日**（訓練資料有時效性）、**幻覺問題**（模型可能生成看似合理但錯誤的內容）、**專業知識缺失**（企業內部文件不在訓練資料中）。透過檢索增強，回答變得有根據、可追溯回原始文件。

現代 RAG 系統已從單一向量搜尋進化為混合搜尋架構：結合 BM25 關鍵字搜尋 + 向量語義搜尋 + RRF 融合排序，再透過交叉編碼器（Cross-encoder）重排序提升精準度。知識圖譜增強的 RAG（GraphRAG）能沿邊推理發現隱含連結，支援多跳推理，大幅提升 Token 效率。增量索引技術讓頻繁更新的企業文件只需索引變更部分，降低計算成本。

## 關鍵要素

- **混合搜尋** — BM25 關鍵字 + 向量語義 + RRF 融合排序，比單一向量搜尋更精準
- **知識圖譜增強** — 提取實體與關係，支援多跳推理，Token 效率顯著提升
- **文件解析品質** — 上游解析品質決定下游 RAG 效果，表格錯位會沿管線放大
- **增量索引** — 只索引變更部分，降低頻繁更新場景的計算成本
- **重排序** — Cross-encoder 對候選結果精確評分，優化最終回用品質
- **引用追溯** — 回答附帶具體文件和段落引用，實現可驗證性
- **即時 RAG 管線** — 自動偵測資料源變更並即時重新索引，保持知識庫與資料源同步。[[Pathway]] 等框架實現增量式即時索引——當文件新增、修改或刪除時，只重索引變更部分，而非全量重建。這解決了傳統 RAG 批次索引的延遲問題，適合資料頻繁更新的企業場景。
