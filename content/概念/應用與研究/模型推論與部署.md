# 模型推論與部署

> LLM 模型從訓練完成到實際服務使用者的過程：推論優化、部署架構、成本控制。

## 核心內容

模型推論與部署是 LLM 從訓練完成到實際服務使用者的全過程。推論（Inference）是模型接收輸入並生成輸出的過程，部署（Deployment）是讓推論服務穩定、高效、可擴展地運行。這個領域的核心挑戰是：如何在控制成本的前提下，提供低延遲、高吞吐的推論服務。

推論與訓練的本質不同：訓練是一次性的大量計算，推論是每次請求都需要計算的持續性服務。推論優化聚焦三個方向——Flash Attention 減少 GPU 記憶體搬運加速計算、KV Cache 避免重複計算已生成的鍵值對、以及位置編碼演進讓模型處理更長序列。這些底層技術讓大模型在有限的 GPU 記憶體中高效運行。

部署架構依規模和場景而異：個人開發用 Ollama 在本地一鍵運行模型；生產環境用 vLLM 提供高吞吐的 OpenAI 相容 API；多模型場景用 LiteLLM 統一 API 代理。成本控制則透過量化（降低精度換取速度）、Token 優化（減少輸入 token 數）、Cache Input（共用前綴 KV Cache）和模型選擇（簡單任務用小模型）等策略實現。

## 關鍵要素

- **推論優化** — Flash Attention、KV Cache、GQA/MLA 等技術加速推論並降低記憶體佔用
- **量化壓縮** — 降低模型精度（INT8/INT4）換取速度和記憶體，犧牲少量品質
- **部署架構** — 從單機 GPU 到多節點分散式，依流量和模型規模選擇
- **API 統一** — LiteLLM 等代理統一多個 LLM 供應商的 API 介面
- **成本控制** — Token 優化、Cache Input、Batch API、模型選擇等策略降低推論成本
- **Speculative Decoding** — 小模型預測大模型輸出，加速生成而不犧牲品質

- **vLLM** → PagedAttention 技術，高吞吐推論服務，生產環境首選
  👉 詳見 [[vLLM]]
- **Ollama** → 本地 LLM 運行，一鍵下載和執行模型，開發和個人使用首選
  👉 詳見 [[Ollama]]
- **llama.cpp** → C/C++ 實現的 LLM 推論，CPU 和低 VRAM 環境最佳選擇

- **TensorRT-LLM** → NVIDIA 官方 GPU 最佳化推論引擎

- **LiteLLM** → 統一 API 代理，代理多個 LLM 供應商
  👉 詳見 [[litellm|LiteLLM]]
- **LMCache** → KV Cache 加速，跨實例共享，降低 TTFT
