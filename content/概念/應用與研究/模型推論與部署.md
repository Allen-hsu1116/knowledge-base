# 模型推論與部署

> LLM 模型從訓練完成到實際服務使用者的過程：推論優化、部署架構、成本控制。

## 核心內容

模型推論與部署是 LLM 從訓練完成到實際服務使用者的全過程。推論（Inference）是模型接收輸入並生成輸出的過程，部署（Deployment）是讓推論服務穩定、高效、可擴展地運行。這個領域的核心挑戰是：如何在控制成本的前提下，提供低延遲、高吞吐的推論服務。

推論與訓練的本質不同：訓練是一次性的大量計算，推論是每次請求都需要計算的持續性服務。推論優化聚焦三個方向——Flash Attention 減少 GPU 記憶體搬運加速計算、KV Cache 避免重複計算已生成的鍵值對、以及位置編碼演進讓模型處理更長序列。這些底層技術讓大模型在有限的 GPU 記憶體中高效運行。

部署架構依規模和場景而異：個人開發用 Ollama 在本地一鍵運行模型；生產環境用 vLLM 提供高吞吐的 OpenAI 相容 API；多模型場景用 LiteLLM 統一 API 代理。成本控制則透過量化（降低精度換取速度）、Token 優化（減少輸入 token 數）、Cache Input（共用前綴 KV Cache）和模型選擇（簡單任務用小模型）等策略實現。

## 關鍵要素

- **推論優化** — Flash Attention、KV Cache、GQA/MLA 等技術加速推論並降低記憶體佔用
- **量化壓縮** — 降低模型精度（INT8/INT4）換取速度和記憶體，犧牲少量品質
- **部署架構** — 從單機 GPU 到多節點分散式，依流量和模型規模選擇
- **API 統一** — LiteLLM 等代理統一多個 LLM 供應商的 API 介面
- **成本控制** — Token 優化、Cache Input、Batch API、模型選擇等策略降低推論成本
- **Speculative Decoding** — 小模型預測大模型輸出，加速生成而不犧牲品質

## 各框架的做法

- **Miles** → 以 SGLang 產生 rollout、Megatron-LM 執行分散式訓練，支援大模型與 Agent 的非同步強化學習後訓練
  👉 詳見 [[radixark-miles\|Miles]]
- **Magnitude** → 先分析本機晶片、記憶體與頻寬，再推薦、下載和調校適合 Agent 使用的本地模型
  👉 詳見 [[magnitudedev-magnitude\|Magnitude]]
- **vLLM** → PagedAttention 技術，高吞吐推論服務，生產環境首選
  👉 詳見 [[vLLM]]
- **Ollama** → 本地 LLM 運行，一鍵下載和執行模型，開發和個人使用首選
  👉 詳見 [[Ollama]]
- **llama.cpp** → C/C++ 實現的 LLM 推論，CPU 和低 VRAM 環境最佳選擇
  👉 詳見 [[llama-cpp\|llama.cpp]]
- **SGLang** → 推論加速框架，支援多模態和結構化生成
  👉 詳見 [[sgl-project-sglang\|SGLang]]
- **TensorRT-LLM** → NVIDIA 官方 GPU 最佳化推論引擎
  👉 詳見 [[NVIDIA-TensorRT-LLM\|TensorRT-LLM]]
- **LiteLLM** → 統一 API 代理，代理多個 LLM 供應商
  👉 詳見 [[litellm\|LiteLLM]]
- **LMCache** → KV Cache 加速，跨實例共享，降低 TTFT
  👉 詳見 [[LMCache-LMCache\|LMCache]]
- **Bonsai** → 1-bit / Ternary 超低精度 LLM，27B 模型壓到 iPhone 可跑，Q1_0 已併入 llama.cpp
  👉 詳見 [[PrismML-Eng-Bonsai-demo\|Bonsai Demo]]
- **Outlines** → 結構化生成函式庫，生成時 logits mask + CFG 保證輸出結構，跨 OpenAI/vLLM/Ollama/transformers/llama.cpp
  👉 詳見 [[dottxt-ai-outlines\|Outlines]]
- **oMLX** → Apple Silicon 推論伺服器，以 continuous batching、RAM＋SSD 分層 KV Cache 和 macOS 原生管理服務本地模型
  👉 詳見 [[jundot-omlx\|oMLX]]
- **Modular Platform** → 以 Mojo、MAX、加速 kernels 與 OpenAI 相容 serving 統一 AI 開發到部署
  👉 詳見 [[modular-modular\|Modular Platform]]
- **ONNX Runtime** → 以 ONNX graph 與 Execution Providers 將不同訓練框架模型部署到 CPU、GPU、NPU、行動與 Web
  👉 詳見 [[microsoft-onnxruntime\|ONNX Runtime]]
- **OBLITERATUS** → 研究拒答方向、權重投影與 steering vector，並驗證模型修改後的 refusal、perplexity 與 coherence
  👉 詳見 [[elder-plinius-OBLITERATUS\|OBLITERATUS]]
- **Marin** → 從資料策展、預訓練和後訓練一路記錄到評估 artifacts，補足模型服務之前的研發生命週期
  👉 詳見 [[marin-community-marin]]
