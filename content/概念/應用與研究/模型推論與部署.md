## 是什麼

模型推論與部署是 LLM 從訓練完成到實際服務使用者的全過程。推論（Inference）是模型接收輸入並生成輸出的過程，部署（Deployment）是讓推論服務穩定、高效、可擴展地運行。這個領域的核心挑戰是：如何在控制成本的前提下，提供低延遲、高吞吐的推論服務。

## 核心特色

- **推論 vs 訓練**：推論是模型「用」的階段，訓練是「學」的階段；推論優化聚焦延遲、吞吐量和成本
- **推論優化三劍客**：Flash Attention（少搬資料）、KV Cache（存下來不重算）、Positional Embedding 演進（位置編碼更精準）
- **多種部署架構**：本地單機（Ollama）、生產叢集（vLLM）、API 代理（LiteLLM），各有適用場景
- **成本控制**：量化、剪枝、蒸餾三種方法壓縮模型，降低 GPU 記憶體和推論成本

## 推論 vs 訓練

| 階段 | 特點 | 成本 |
|------|------|------|
| 訓練 | 大量 GPU、長時間、一次性 | 極高 |
| 推論 | 每次請求都需計算、持續性 | 中等但累積 |

## 怎麼用

### vLLM（生產環境首選）

```bash
pip install vllm

# 啟動 OpenAI 相容伺服器
vllm serve meta-llama/Llama-3.1-8B \
  --tensor-parallel-size 2 \
  --max-model-len 8192
```

### Ollama（本地開發）

```bash
# 安裝
curl -fsSL https://ollama.com/install.sh | sh

# 下載並執行模型
ollama run llama3.1
```

### LiteLLM（統一 API 代理）

```bash
pip install litellm

# 代理多個 LLM 供應商
litellm --model gpt-4 --model claude-3-opus
```

## 成本控制

- [[rtk|RTK]]：減少送給 LLM 的 token（60-90% 節省）
- Cache Input：共用前綴的 KV Cache（OpenAI 打 1 折）
- 模型選擇：簡單任務用小模型，複雜任務用大模型
- Batch API：非即時請求用批次處理
