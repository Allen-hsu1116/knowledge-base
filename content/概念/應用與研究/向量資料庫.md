# 向量資料庫

> 儲存和檢索向量嵌入（embeddings）的專用資料庫，是 RAG 和語意搜尋的基礎設施。

## 核心內容

向量資料庫專門用來儲存高維向量（embeddings），並提供快速的近似最近鄰搜尋（ANN）。在 LLM 應用中，文字先透過 embedding 模型轉成固定維度的向量，再透過向量資料庫做語意搜尋——根據「意義」而非「關鍵字」來找資料。這使得向量資料庫成為 RAG（檢索增強生成）和語意搜尋管線的核心儲存層。

在 RAG 管線中，文件先被切塊、轉成 embedding、存入向量資料庫；查詢時，使用者問題也轉成 embedding，透過 ANN 搜尋找到最相關的文件片段，再餵給 LLM 生成回答。這個流程讓 LLM 能存取大量外部知識，而不需要將所有內容塞進 context window。

向量資料庫的關鍵技術包括索引演算法（HNSW、IVF、PQ 等）用於加速搜尋、距離度量（cosine similarity、L2、inner product）用於計算向量相似度，以及儲存最佳化來降低大規模向量集合的記憶體佔用。不同資料庫在效能、規模、易用性和部署方式上各有取捨。

## 關鍵要素

- **Embedding 儲存** — 將文字、圖片等非結構化資料轉成固定維度的向量表示並持久化儲存
- **ANN 搜尋** — 近似最近鄰搜尋，犧牲少量精度換取大幅加速，支援百萬級向量的即時查詢
- **索引演算法** — HNSW、IVF、PQ 等資料結構加速搜尋，不同演算法在召回率和速度間取捨
- **距離度量** — cosine similarity、L2 distance、inner product 等，依資料特性選擇
- **混合檢索** — 向量搜尋結合關鍵字搜尋或知識圖譜，提升檢索精確度
- **過濾與元資料** — 在向量搜尋的同時依元資料（如時間、標籤）過濾結果

## 各框架的做法

- **Chroma** → 輕量 Python 友善的向量資料庫，API 極簡，適合快速原型開發
  👉 詳見 [[Chroma]]
- **Milvus** → 大規模分散式向量資料庫，支援 GPU 加速，適合企業級場景
  👉 詳見 [[Milvus]]
- **Qdrant** → Rust 實現的高效向量資料庫，效能導向，支援豐富的過濾條件
  👉 詳見 [[Qdrant]]
- **LEANN** → 本地隱私優先，透過圖形重算實現 97% 儲存節省
  👉 詳見 [[yichuan-w-LEANN]]
- **Elasticsearch** → 分散式搜尋引擎兼向量資料庫，支援混合搜尋（全文 + 向量），RAG 場景熱門
  👉 詳見 [[elastic-elasticsearch]]
- **Supabase (pgvector)** → PostgreSQL 擴充提供向量搜尋，一體化後端含認證/儲存/即時
  👉 詳見 [[supabase-supabase]]
- **turbovec** → Rust 向量索引，基於 TurboQuant 無訓練量化，16x 壓縮，SIMD 加速搜尋比 FAISS 快
  👉 詳見 [[RyanCodrai-turbovec]]
